Vom Property zum FormElement

AnnotatedObjectParser.Parse(obj) liest per Reflection alle öffentlichen Properties eines beliebigen Objekts. Aus Datentyp, Nullbarkeit und Annotationen entsteht pro Property ein FormElement. Die fertige FormElementList zeigt der FormElementRenderer als Formular an.

Eingabe: ein annotiertes Property
[Group("Ihre Kinder")]
[Label("Kinder", "Ihre Kinder")]
[Range(0, 10)]
public int? Kinder { get; set; }
→
Ausgabe: FormElement
Key      = "Kinder"
Label    = "Kinder"
Note     = "Ihre Kinder"
Group    = "Ihre Kinder"
Min, Max = 0, 10
Required = false  // int? ist nullable
Type     = Range  // Zahl + [Range]
Der Weg im Überblick

Eine Schleife über alle Properties

Für jedes Property laufen dieselben Schritte. Zuerst kommen Kapitel und Überschriften, dann der Ausschluss per [Hidden], danach wird das eigentliche Element gebaut. Den Feldtyp bestimmt eine feste Prüfreihenfolge: Der erste Treffer gewinnt.

Kern des ParsersSonderfall: Struktur, Info oder ausgelassenSchleife über die Properties

Annotation für Annotation

  
Alle ausgewerteten Annotationen

  
Der Parser wertet neun eigene Annotationen aus ITVisions.Util und 17 Standard-Annotationen aus .NET aus, dazu zwei Attribute, die der Compiler selbst erzeugt. Liefern eine eigene und eine Standard-Annotation denselben Wert, gewinnt die eigene.

Werte und Anzeige

     
[DefaultValue(wert)]System.ComponentModelValue, solange das Property noch den Standardwert seines Typs hat (null, Leerstring, 0, false …). Ein gesetzter Wert bleibt erhalten.

     
[DisplayFormat(DataFormatString, NullDisplayText, ApplyFormatInEditMode)]Format = DataFormatString. Struktur und Reihenfolge

     
[Chapter(title)]Eigenes FormElement vom Typ Chapter vor dem Feld, also eine neue Seite im Renderer

     
[Headline(title)]Eigenes FormElement vom Typ Headline vor dem Feld (nach einem Chapter)

     
[Hidden]Blendet das Property in beiden Modi aus. Chapter und Headline am selben Property entstehen trotzdem.

     
[Hidden(hideEdit, hideDisplay)]HideEdit blendet im Bearbeitungsmodus aus, HideDisplay im Anzeigemodus. [Hidden(false, true)] zeigt ein Feld also nur im Formular, [Hidden(true, false)] nur in der Anzeige.

     
[Display(Order = n)]Sortiert die Properties. Ohne Order kommen sie ans Ende, in Deklarationsreihenfolge.

Zwei Modi

  
Bearbeiten oder nur anzeigen

  
Der optionale zweite Parameter von Parse() legt fest, wofür die Liste gedacht ist. Ohne Angabe gilt FormElementMode.Edit, bestehende Aufrufe ändern sich also nicht.

  

   

    
AufrufAusgeblendetFelder

    
     
Parse(obj)[Hidden], [Hidden(true, …)]Editierbar, Pflichtfelder wie beschrieben

     
Parse(obj, FormElementMode.Display)[Hidden], [Hidden(…, true)]Alle gesperrt, keine Pflichtfelder. Werte mit [DisplayFormat] erscheinen formatiert, auch Zahlen und Datumswerte.

Pflichtfelder

  
Nullbarkeit entscheidet mit

  
Ohne [Required] wird ein Feld zum Pflichtfeld, wenn sein Typ keinen null-Wert zulässt. Bei Referenztypen liest IsPropertyNullable() dafür die Compiler-Attribute NullableAttribute und NullableContextAttribute. So funktioniert das auch ohne NullabilityInfoContext unter .NET Standard 2.0.

Gruppen

  
Drei Bedeutungen von GroupName

  

   
null
Kein [Group] und kein GroupName. Der Renderer zeigt das Feld einzeln in voller Breite.

   
"" (leer)
Aufeinanderfolgende Properties mit leerem Namen bekommen denselben Namen AutoGroupPrefix + N. Sie stehen nebeneinander, ohne Rahmen und Legende. Beispiel: Anrede und Titel.

   
"Ihre Kinder"
Benannte Gruppe. Benachbarte Felder mit gleichem Namen stehen in einer Zeile, mit Rahmen und dem Namen als Legende.
