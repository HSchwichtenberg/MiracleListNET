www.IT-Visions.de Formular-Pipeline

Ein Formular entsteht aus einem .NET-Objekt oder einer Markdown-Vorlage. Zwei Parser übersetzen eine annotierte .NET-Klasse oder eine Markdown-Vorlage in dieselbe FormElementList. Der FormElementRenderer macht daraus ein validiertes Blazor-Formular und schreibt die Eingaben zurück.

Überblick

Zwei Eingänge, ein Format, ein Renderer

Die Kästen mit Pfeil führen zum jeweiligen Schaubild. Die FormElementList ist die gemeinsame Schnittstelle: Der Renderer weiß nicht, aus welcher Quelle sie stammt.

Ein durchgehendes Beispiel

Ein Feld auf seinem ganzen Weg

Alle drei Schaubilder verwenden dieselben Felder aus der Klasse Fragebogen in ITVForms. Hier ist das Feld Email in allen vier Formen.

1 · C#-Property
[Label("Email", "Die Annotation [EmailAddress] prüft, ob es sich um eine gültige E-Mail-Adresse handelt.")]
[Required]
[EmailAddress]
public string? Email { get; set; }
1 · oder Markdown-Zeile
+ Email {Die Annotation [EmailAddress] prüft, ob es sich um eine gültige E-Mail-Adresse handelt.}: [Email]

+ macht das Feld zum Pflichtfeld, {…} ist der Hinweis, [Email] der Typ.

2 · FormElement
Key      = "Email"  // Markdown: "Benutzerkonto_Email"
Label    = "Email"
Type     = FormElementType.Email
Required = true
Note     = "Die Annotation [EmailAddress] prüft, ob es sich um eine gültige E-Mail-Adresse handelt."
3 · Steuerelement
<label class="fw-bold">Email
 <span class="text-danger" title="Pflichtfeld">*</span>
 <span class="info-icon" data-tooltip="…">ℹ️</span>
</label>
<input type="email" class="form-control" required>
Quellen: ITVisions.Blazor/Controls/FormElementRenderer.razor(.cs) im Repository MiracleListNET, Typen AnnotatedObjectParser und MarkdownFormDSLParser sowie FormElement, FormElementList und FormElementType aus dem NuGet-Paket ITVisions.Util
